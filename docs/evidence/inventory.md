# PR1 evidence index: binary and help inventory

This document records what PR1 established from the supplied files. It is an
inventory and evidence index, not a rules specification. No original program
was executed, no code was disassembled, and no gameplay formula is claimed.

|---|---:|---|---|
| `stars26i.exe` | 3,216,832 | `5770dade2db0e11918631d5c128c0bf7ab48e371f7b2267a4ff02531bb8e198e` | Observed; matches `PLAN.md` |
| `Stars! - RIP/stars!.hlp` | 1,631,113 | `9c5cb10fd5e5d201813fcf6f470c495f290b322ee21e1795418a8412393270d1` | Observed; hash recorded by PR1 |

The executable is a segmented 16-bit Windows NE (New Executable) GUI
application. The help container identifies itself as a Windows 3.1 HLP file.
Both files are supplied inputs and remain outside Git. `Stars! - RIP/code.txt`
was not read, logged, or included in any report.

Evidence classes used below:

- **Observed**: read directly from the supplied bytes by the tools.
- **Statically derived**: computed from parsed structures without execution.
- **Documented-only**: stated by decoded help or external format documentation.
- **Lead**: a name, string, or caption worth follow-up; not proof of runtime
  behaviour.
- **Unknown**: not established by PR1.

## Reproduce

```sh
python3 tools/analysis/inventory.py stars26i.exe --output analysis/inventory.json
python3 tools/analysis/help.py 'Stars! - RIP/stars!.hlp' \
  --output analysis/help/inventory.json \
  --text-output analysis/help/topics.txt
python3 -m unittest discover -s tools/analysis/tests -v
sha256sum stars26i.exe 'Stars! - RIP/stars!.hlp'
```

`analysis/` is ignored. The committed tools, synthetic fixtures, and this
index are the reproducible artifacts; raw decoded help and generated reports
stay private.

## NE executable inventory

The report is generated by `tools/analysis/ne.py` and
`tools/analysis/inventory.py`. Two runs on the same input produced
byte-identical JSON.

### Headers and segments

- DOS `MZ` header; `e_lfanew` at `0x3c` is `0x400`. The NE signature is at file
  offset `0x400` (observed).
- NE linker version 5.60; flags `0x0302`; expected Windows version 3.10; target
  OS 2 (Windows); file alignment shift 6 (64-byte sectors); additional flag
  `FAST_LOAD_AREA` (statically derived).
- 35 segments; 6 module references; 38-byte nonresident-name table; 53 movable
  entries. CS:IP is segment 34:offset `0x001a`; SS:SP is segment
  35:offset `0x0000`. These are reported as addresses, not disassembled code.
- Entry table: one movable bundle with 53 entries. All are reported as
  exported/movable; no code semantics are inferred.
- Segment 34 (code) starts at file offset `0x50dc0`, length 14,391 bytes.
  Segment 35 (data) starts at file offset `0x54e40`, length 26,248 bytes.
  Segment-relative offsets are kept distinct from file offsets throughout the
  report.

## Help container

### Provenance and metadata

The help container is a WinHelp 3.1 file. Decoded metadata:

- HLP magic `0x00035F3F`; directory start `1,028,147` (`0x0fb033`); no free
  list.
- Declared file size `1,631,041`; actual size `1,631,113`. The last declared
  internal file ends at the declared size; 72 trailing bytes were not parsed.
- Title: `Stars! Player's Guide  (Jan 10, 1998)`; copyright:
  `Copyright 1998 Mare Crisium, LLC`.
- `|SYSTEM` at file offset `3,013` (used size 542): minor version 21 (HC31 /
  Windows 3.1), major 1, flags 0, no LZ77 compression, 4,096-byte physical
  topic blocks.
- Raw generation date `884,558,967`. Interpreted with the Unix epoch this is
  `1998-01-11T22:49:27Z`; `file` presents it as `Mon Jan 12 00:49:27 1998`
  local time. Both are January 1998. The documented 1980 epoch would produce
  2008 and is contradicted by the title and file date, so the JSON records the
  raw value and labels the epoch explicitly.
- 142 internal files: nine non-bitmap files (`|CONTEXT`, `|CTXOMAP`, `|FONT`,
  `|KWBTREE`, `|KWDATA`, `|KWMAP`, `|SYSTEM`, `|TOPIC`, `|TTLBTREE`) and 133
  bitmaps `|bm0` through `|bm132`. There is no `|Phrases`, `|PhrIndex`, or
  `|PhrImage`.
- `|TOPIC` at file offset `3,564` (used size 623,138): 4,274 links; 419 topic
  headers, 3,679 display records (`0x20`), and 176 table records (`0x23`).

### Decoding workflow

`tools/analysis/help.py` parses the HLP header, the internal directory B+ tree,
FILEHEADERs, `|SYSTEM`, and `|TOPIC`. It implements WinHelp LZ77 and old-style
`|Phrases` decompression; Hall `|PhrIndex`/`|PhrImage` is detected and
reported as unsupported rather than guessed. For this file, topics are
uncompressed and no phrase table is present. All 419 titles were decoded;
body text is best-effort. Eighteen display/table records in six topics fell
back to their NUL-separated strings (`strings-only`), and table cell geometry
is not reconstructed.

The decoded topic text is written to the ignored path
`analysis/help/topics.txt`. The JSON index records TOPICPOS and absolute HLP
byte offsets for every topic.

## Disassembly tooling availability

Checked on 2026-10-17:

- `objdump` is installed but does not recognise the NE container:
  `objdump: stars26i.exe: file format not recognized`.
- `objdump` does support raw 16-bit disassembly:
  `objdump -D -b binary -m i8086 <extracted-segment.bin>`.
- `llvm-objdump` is installed but rejects the NE container and does not accept
  the GNU `-b binary` mode.
- `ndisasm` and `winedump` were not on `PATH`.

A compatible workflow is therefore: use the checked parser to locate a
segment's file offset and length, extract exactly that byte range to ignored
`analysis/`, then disassemble the raw segment with GNU `objdump -b binary -m
i8086`. Segment-relative addresses, relocations, and WINDOWS API imports must
be tracked separately; a raw disassembly is not a code cross-reference by
itself. PR1 did not perform disassembly.

## Limitations and unresolved evidence

- No original game was executed. No VM or operator run is claimed.
- No disassembly or code cross-reference was performed, so dialog/procedure/
  control relationships remain leads.
- Dialog templates are best-effort. All 36 in this binary decoded, but a
  malformed dialog would be recorded as a parse error rather than treated as
  behaviour.
- String references are selected ASCII leads with bounded windows, not a
  complete string-table inventory. Absence of a string does not prove absence
  of a code path.
- Resource length units and resource-name offset bases are recorded as
  observed in this binary; they conflict with some generic NE descriptions and
  need comparison with other NE files if they become a shared contract.
- The help parser's body text is best-effort for table records; 18 records in
  six topics are `strings-only`. Table cell geometry is not reconstructed.
- The help generation-date epoch is observed as Unix-compatible in this file,
  contrary to the cited format note's 1980 base. The raw value and both
  interpretations are retained.
- Seventy-two trailing bytes after the HLP declared size were ignored. They do
  not belong to any declared internal file in the parsed directory.
- The help is dated January 1998 while the executable has a 2002 file date and
  reports `Version 0.1`. Version applicability is unresolved.

## Prioritized questions for PR2

1. Correlate exported procedures `RACEWIZARDDLG1`–`RACEWIZARDDLG6` with
   dialog resources `#146`–`#151` using entry-table addresses and controlled
   disassembly/xrefs.
2. Map every control ID in dialogs `#149` (primary traits) and `#150` (lesser
   traits) to a trait identity, and map `#151` cost choices to research fields.
3. Trace the `Turindrones` string at segment 35 relative `0xa06` to its code
   references and determine whether it is an opponent preset, a race name, or
   both.
4. Recover the advantage-point formula, trait costs, exclusions, and defaults
   from the executable or controlled experiments, with confidence labels.
5. Establish whether the January 1998 help's numeric claims match
   `stars26i.exe`, especially trait costs, research-cost modifiers, population
   efficiency, and Alternate Reality rules.
6. Identify custom resource types 10000, 10002, and 10004 and their runtime
   consumers.
7. Resolve `#209` New Game's race-selection path: the `&Customize Race...`
   control, predefined-race list, and relationship to `#146`–`#151`.
8. Decide whether resource length/name-offset conventions need a shared parser
   contract or remain documented per-input observations.
9. Design controlled operator scenarios for anything that cannot be recovered
   statically; do not invent observations without a runnable environment.
